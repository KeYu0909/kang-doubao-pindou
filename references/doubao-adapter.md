# 0.3.0执行优先级

当前入口以SKILL.md和[Fast Path](fast-path.md)为准：像素阶段纯本地，不再调用图片生成工具做“像素简化”；旧版pixel导入协议仅保留读取/测试兼容。确定性需求直接调用固定脚本，每个图阶段得到候选就交付。用户需要去背景/创意修改时合并一次宿主图片编辑，不现场写抠图代码。安装首次提示仍必须执行。

# 豆包适配边界与宿主接口

本轮没有进入豆包账号或客户端，没有发起生成式图片调用。PDF改版在本机复用已授权的现有网格及程序生成测试数据，没有上传私人图片。当前实现的是“宿主组织调用 + 本地确定性制图 + 真实文件导入”的适配接口，并非已通过豆包集成验收。

| 能力 | 本轮结论 | 用户真实环境需要核实 |
|---|---|---|
| 标准SKILL.md及ZIP目录 | 本地检查/解压通过，见报告 | 豆包具体入口是否接受此格式 |
| 读写工作文件、执行Python | 本地已执行 | 豆包是否暴露执行工具及持久目录 |
| 豆包原生编辑工具名/参数 | 未知 | 使用当前真实工具文档/工具列表，不套用其他宿主工具名 |
| 一次编辑多个明确要求 | 提示及操作记录支持 | 实际去背景、加帽和保留特征质量 |
| 图片结果文件自动传递 | 未知 | 返回可读文件、附件或可下载链接的具体形式 |
| 宿主原生工具中断 | 未知 | 手动取消测试及实际进程行为 |
| 宿主调用/交付时间戳 | 未知 | 可记录字段、截图/录屏时间依据 |
| 每阶段端到端60秒 | 待实测 | 包含排队、下载、校验、交付的完整真实时间 |
| 跨会话状态恢复 | 本地文件恢复有测试 | 豆包目录保留方式与上传导出能力 |

## 安装前置要求

调用任何制图流程前，必须先执行SKILL.md第零步，提示并检查[持久化安装与恢复](persistent-install.md)。读取宿主实际持久目录约定，核实源码、.venv和作品路径；不能默认/runtime会保留，也不能默认/home/user必然持久。若运行环境重置，只从真实保存的安装与作品恢复，不重新绘制历史图。当前没有验证豆包不同客户端的目录保留期限，成功安装不等于跨会话保存已验证。

## 已实现的真实文件导入接口

1. `init`读取用户实际图片，取得EDIT_REV。
2. `begin --kind edit --base EDIT_REV --request '去背景，加红色生日帽；保留姿态、绿色眼睛与毛色' --preserve '姿态、眼睛、毛色'`。
3. 查看返回的真实`source_file`，不要自行寻找替代图片。当前候选修改基于该文件。保存`operation_id`和`source_sha256`。
4. 宿主能力确已核实时，用 `claim-call --operation OP --mode host`记录本轮一次调用，然后调用**实际可用**工具一次，全部要求合并，不自动重绘。该命令只记录次数，不会调用任何图片服务；工具失败也已消耗本轮调用次数。
5. 真实结果可读后：

```bash
.venv/bin/python scripts/pindou.py edit --project "$WORK" \
  --operation OP --input /实际结果.png --based-on-sha SOURCE_SHA --origin host
```

6. 只展示这一版候选并等待确认。用户“帽子小一点”需以新候选为基准重新begin；旧图自动保留。

`claim-call`约束通过此脚本组织的一轮最多一次，不可阻止宿主绕过脚本调用。不要将一次失败后新建operation无限重试解释成满足“一轮一次”；新operation应对应用户新一轮明确修改。

## 手动回退路径

若豆包有编辑图片能力但无法向脚本传可读文件，用户手动保存真实候选，在本机对同一操作导入：

```bash
.venv/bin/python scripts/pindou.py edit --project "$WORK" \
  --operation OP --input /用户实际保存的结果.png --based-on-sha SOURCE_SHA --origin manual
```

记录为manual，不算自动链路通过。工具实际调用次数无法取得时记录unknown；不能因为本地脚本没生图就推断宿主也没生图。若尚无图片，只请求提供原图，不对不存在的文件执行后续流程。

## 可选像素简化

仅在编辑版本已明确确认且确需简化时：`begin --kind pixel --base 当前版本 --request '简化细节，保留已确认主体和指定特征，不添加图纸网格或文字'`，claim一次真实宿主调用，然后：

```bash
.venv/bin/python scripts/pindou.py pixel --project "$WORK" --base 当前版本 \
  --input /实际简化结果.png --operation OP --based-on-sha SOURCE_SHA \
  --width 78 --height 78 --max-colors 18
```

固定脚本最后强制精确网格和色数。AI像素风图片本身不是网格预览。修改颜色数不需要再次调用AI，直接pixel重用当前保存的source。

## 不能推断的事实

- 豆包对技能ZIP支持不能由其他平台支持Agent Skills推断。
- 此处不写假设存在的豆包API、工具名称、鉴权参数、下载域名或客户端菜单路径。
- 模拟调用使用`claim-call --mode simulated`、`--origin simulated`，只做接口/状态测试；不算真实编辑效果或端到端速度。
- PNG、PDF的用户指引及CSV表头为中文，字体为包内可分发OFL子集；不读取用户私人字体。色号、命令、版本及数据键保留原标识。
