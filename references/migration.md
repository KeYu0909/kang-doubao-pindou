# 0.1 → 0.2 更名与迁移

## 0.3.2 安装入口升级

旧源码不在豆包扫描路径时，在完整新版包中运行 `python3 install.py`。源码复制到本轮约定的真实 `.user_skills/kang-doubao-pindou/`，在目标新建依赖；源 `.venv` 和作品不搬动。已有目标环境可用则复用；代码覆盖前有备份，未收录的作品不删除。不改作品格式或图像算法。成功后重启对话实际验证发现；不同宿主版本的扫描路径需核实，不使用软链接代替。详见 [安装说明](../README.md)。

正式名从 `yongkang-doubao-pindou` 改为 `kang-doubao-pindou`，显示名“永康玩AI · 拼豆助手”。工程原地更名，不新建另一份业务代码。旧名称只在迁移说明、基线或真实历史来源记录中保留，不能对历史来源字符串盲目全局替换。

1. 保留旧技能安装与用户完整作品目录备份，包括state.json/revisions/events.jsonl。不要自动删除旧技能，不单独复制一个PNG当完整项目。
2. 先按[持久化安装说明](persistent-install.md)确定宿主保留目录，将新ZIP解压到其中的独立新版技能目录 `kang-doubao-pindou/`，按README重建.venv并doctor。将后续启动命令统一指向新版绝对路径；同一个作品目录不要同时交给两个版本操作。
3. 用新CLI对旧作品目录执行status和validate；读取schema_version=1，原project_id、revision_id、路径、网格哈希与原确认保留。新增interaction/preferences/pending_modification为可选字段，无破坏性迁移。旧skill_version保留为项目创建版本，不假装原项目由新版创建。
4. 旧PNG明确确认继续有效，导出时仍绑定原网格/文件哈希。旧确认缺project_id/source时仅在原项目作用域兼容；新的上下文确认必须记录完整字段和当前会话真实展示。旧会话无present回执时先实际展示原文件，不能自动补历史展示证据。
5. 旧PDF保持原文件及旧参数；新模板创建独立PDF缓存项，同版本同新布局重复导出复用。PNG/CSV不因更名重新生成。跨路径迁移依赖相对成品路径；真实编辑来源的历史绝对路径可保留，不用它覆盖现有文件。
6. 客户端若同时发现新旧技能，请明确调用 `kang-doubao-pindou`。核验新版可用后，用户可自行通过客户端停用旧技能或将旧目录移到技能搜索路径以外；本项目不自动卸载或清理它。豆包具体停用/导入菜单需在实际客户端核实。

开发目录中的.baseline/v0.1保留旧生成器、测试与真实10页反馈PDF，仅供本机验证，不进入ZIP。发布包不含任何用户项目。


## 中文标注升级

新版png命令会识别旧标注模板，保留原PNG及小图的文件和哈希记录，另存中文PNG；网格和色号不变。旧PNG确认移入confirmation_history，不自动授权哈希不同的中文PNG。中文图纸真实展示后，用户下次直接说“导出PDF”即可在同轮完成该文件确认与导出，不要求口令。已有历史PDF继续保留。

PDF中文模板为overview-guide-build-v3-zh；CSV中文表头模板为csv-zh-v1。缓存键包含模板，旧文件检查器仍能读取英文CSV/旧版PDF。中文CSV字段为色板、色号、颜色值、用量（颗）、建议备损（颗）、作品版本、网格校验值；对接程序请据此更新列名。旧英文文件不覆盖。

## 0.2.1 已安装智能体如何升级

本次更新的是启动提示与安装恢复协议，Python依赖和作品格式不变。之前安装的智能体需要重新同步或更新Skill文件，才能读到新的SKILL.md及references/persistent-install.md；GitHub推送不代表宿主内已有副本自动更新，是否自动拉取须依据宿主实际能力。

- 已有安装位于宿主支持保留的目录、doctor通过：更新完整技能文件即可，保留并复用.venv，不重新安装依赖。
- 原安装位于/runtime等临时目录：迁移完整技能到确认支持保留的最终目录，在新位置创建虚拟环境；保留原作品和旧安装，不直接搬迁旧.venv。
- 当前环境已被重置：先查持久目录与项目备份，只恢复缺失部分，不能重建相似作品代替真实历史。

更新后首次调用会提示并检查持久化，后续正常使用不重复提示安装。宿主具体的更新/重新导入入口需要在实际界面确认。


## 0.3.0升级

更新完整技能文件后复用现有依赖（锁定版本未变化），不删除原图、state.json、revisions或events.jsonl。schema_version仍为1，旧名称与0.2.x项目无需迁移重建。新网格新增可选protection和analysis文件，去杂色新revision保留父版本且不继承确认。

当前网格仅修改max-colors时保留格子布局和清理结果，从当前色号重映射；修改尺寸、输入或色板仍使用原有采样流程。旧人工清理网格的真实cells照常读取，不根据聊天重新构造。

新宿主用--current与route，旧--base/--revision调用继续兼容。升级Skill不自动更新智能体里的旧副本，需在原智能体更新一次。GitHub主分支与Release仅在实际上传后才算同步，不能以本地打包代替发布。
