# 持久化安装与恢复（0.2.1）

此流程在任何新作品的init、编辑或像素化之前执行。已有正常安装在后续轮次直接复用。它是宿主执行协议，不是能够改变宿主存储策略的脚本。

## 先说明，再检查

首次向用户说明：

> 开始前，我会先检查技能、依赖和作品的保存位置。已有可用安装会直接复用；需要安装时，优先放到宿主支持的持久目录，避免临时运行环境重置后反复安装。

先读取宿主提供的目录说明或当前项目的安装记录。记录实际技能根目录、作品目录、宿主说明依据和保留范围（例如仅本项目或跨会话）。检查路径是否可读写，并解析软链接确认实际存放位置。这些检查只能确认当前可用性；不能通过创建一个文件就证明跨重置持久化。

- `/runtime`、`/tmp`、`/var/tmp`等临时运行目录不存放唯一的源码、虚拟环境和作品。
- `/home/user/.pindou-skill/`只是候选，必须结合实际宿主约定判断。不要照搬截图路径到其他宿主。
- 源码和`.venv`需位于同一稳定安装目录；作品单独存入宿主支持保留的项目目录。必要的入口软链接只作入口，不承担保存功能，不覆盖已有真实目录。
- 若宿主仅保留项目文件而不保留可执行环境，将完整技能包及作品备份保存到项目文件；临时执行环境失效后可能仍需重建依赖，不能承诺免安装。
- 若无任何持久化依据，提前说明“当前只能确认本次会话可用”，使用可下载的备份文件保留成果；不要连续尝试重装来冒充修复。只有确实无法确定目标目录时才向用户询问一次。

## 安装与复用

1. 查已记录的绝对安装路径，而不是只检查当前工作目录。源码根目录须有SKILL.md、scripts/pindou.py、requirements.lock及assets/。
2. 若已有`.venv/bin/python`，用该解释器和实际脚本绝对路径运行doctor。成功就复用已有环境，不再下载、创建虚拟环境或安装依赖。
3. 首次安装：从完整发布包或GitHub main分支取得完整文件树；校验包内MANIFEST.json，然后解压/复制到最终稳定目录。不要只复制SKILL.md，也不要把开发目录的用户作品、缓存和私人文件当技能发布。
4. 在最终目录创建`.venv`，按README用`python -m pip install --require-hashes -r requirements.lock`安装固定依赖，然后doctor。已有环境仅依赖缺失或不匹配时修复依赖；解释器失效或安装路径迁移时，保留旧环境，另建可用环境。不能直接搬迁旧虚拟环境后假定能用。
5. 首次安装耗时单独说明，不混入像素/PDF处理耗时。测试套件属于开发验收，不在每次生成时运行。
6. 将实际安装路径、作品路径、技能版本、检查结果与持久化依据记录在宿主确认保留的项目说明文件中，后续按记录调用。同一次会话不要反复询问或报告安装。

安装后只报告真实结果，例如：

> 环境检查通过，后续复用已有安装。技能：〈真实绝对路径〉；作品：〈真实绝对路径〉。宿主声明的保存范围：〈实际范围〉。

占位符须替换为真实检查结果。若只有本次会话验证，明确写本次会话可用，不写“永久保存”或“重启一定不会丢”。

## 临时目录重置后的恢复

1. 先查持久安装的实际绝对路径和解释器；它们仍可用时直接切换回该路径，仅恢复必要的临时入口，不重装。
2. 查原作品的state.json、revisions/、events.jsonl及原图。用原作品目录执行status；首次恢复执行validate。沿用原project_id、revision_id、网格和确认记录。
3. 安装缺失但项目文件保留时，从真实技能备份包恢复安装；作品独立保留，不因修复环境覆盖或重建作品。
4. 只有某部分依赖失效就修复该部分；解释器路径已变则在最终位置重建环境。若解释器版本或系统架构不同，不能复用旧二进制依赖。
5. 缺少真实作品文件时报告缺失项并恢复备份，不根据聊天、预览截图或记忆制造“同一版本”。

正常修改、取消、展示、确认和导出仍遵循原有阶段规则。本次修复不取消用户确认，也不修改图像算法。
