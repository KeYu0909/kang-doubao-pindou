安装后重启同项目对话，实际选择/调用 `kang-doubao-pindou` 并核对 SKILL.md 为 0.3.2。文件可访问而技能不可发现时，核实该版本实际扫描位置和绑定入口；不要反复重装依赖。当前给出的路径与源码不能在本机之外自行改变豆包的扫描规则或保留策略。

下面保留的跨宿主持久记录流程继续适用；历史 `--link` 说明仅用于其他宿主兼容，**不用于本轮豆包源码发现**。`/home/user/.pindou-skill/` 等普通执行位置不能代替本轮约定的 `.user_skills` 扫描入口。

# 0.3.1：持久安装与新窗口发现

安装验收分三项：当前环境能运行、文件在宿主声明的范围内保留、打开新窗口仍能发现入口。`doctor` 只证明第一项；`storage` 会识别已知临时路径并提示其余项未验证。不能把 `/home/user` 可写当成持久证据。

1. 首次调用先提示持久安装。若当前源码或虚拟环境位于临时目录，按下文在宿主确认保留的最终目录安装完整代码和依赖；作品保留在原项目，升级不覆盖作品。
2. 在最终技能目录用其虚拟环境运行下列命令，记录保存到宿主实际保留、后续对话可读取的项目文件目录。`--retention-note` 必须写真实的宿主说明及范围，例如仅原项目内；没有证据就不能登记为持久安装。记录器拒绝已知临时路径（含软链接目标）、系统 Python、外部虚拟环境及冲突记录。

```bash
/实际持久技能目录/.venv/bin/python /实际持久技能目录/scripts/install_record.py record \
  --project /实际持久项目目录 \
  --retention-note '填写宿主实际保存范围与依据'
```

3. 将输出的 `pindou-install.json` 加入宿主可持续读取的项目文件/项目说明；如果可执行文件目录与项目附件存储分离，必须使用宿主真实的文件保存能力，不能把本地写文件当成已上传。项目说明加入：“使用拼豆技能前，先读取项目文件 pindou-install.json，按其中的 skill_path 读取 SKILL.md，使用 python_path 调用脚本；路径缺失时先报告并恢复真实备份，不重建作品。”不要覆盖其他项目说明。
4. 使用宿主真正的技能安装或项目绑定入口，确认技能在当前项目可选择。脚本不提供未知豆包注册 API；无法操作该入口时明确提示用户绑定技能。不能用软链接冒充注册。
5. 在同一项目新建窗口，从项目文件读记录，使用记录中的绝对路径检查：

```bash
/记录的python_path /记录的skill_path/scripts/install_record.py check \
  --record /实际项目文件目录/pindou-install.json
```

返回 `REACHABLE_NOW` 只表示该窗口实际可运行。只有宿主确实新建了窗口、原项目文件及技能入口都可访问时，才报告“已验证同项目新窗口可用”。脚本不会自行将 cross_session_verified 设为真。完全独立的新项目可能使用另一套环境，需要重新绑定或安装。

记录缺失先检查是否打开原项目；技能文件存在但入口没有被加载时修复宿主绑定，不重装依赖；技能或解释器确实消失时按备份恢复。只支持项目附件持久化的宿主需保留完整 ZIP、安装记录和作品，环境重置后可能仍需恢复安装。不要删除旧技能或作品来试缓存。

# 0.3.0最小修复入口

首次检查或真实恢复时运行现有环境的`doctor --repair`。正常就复用且不执行pip；缺失或版本不符只从requirements.lock选出相关发行包，以哈希校验、--no-deps修复。缺临时入口时加`--link /实际入口/kang-doubao-pindou`，已有其他文件不覆盖。此命令不会证明目录持久，不会下载Skill或重建venv，不会运行完整测试。系统Python拒绝自动修复依赖，应使用已建好的持久venv。缓存由pip默认用户缓存保存，必要时仅将PIP_CACHE_DIR设为宿主确认保留的目录。

# 持久化安装与恢复（0.2.1）

此流程在任何新作品的init、编辑或像素化之前执行。已有正常安装在后续轮次直接复用。它是宿主执行协议，不是能够改变宿主存储策略的脚本。

## 先说明，再检查

首次向用户说明：

> 开始前，我会先检查技能、依赖和作品的保存位置。已有可用安装会直接复用；需要安装时，优先放到宿主支持的持久目录，避免临时运行环境重置后反复安装。

先读取宿主提供的目录说明或当前项目的安装记录。记录实际技能根目录、作品目录、宿主说明依据和保留范围（例如仅本项目或跨会话）。检查路径是否可读写，并解析软链接确认实际存放位置。这些检查只能确认当前可用性；不能通过创建一个文件就证明跨重置持久化。

- `/runtime`、`/tmp`、`/var/tmp`等临时运行目录不存放唯一的源码、虚拟环境和作品。
- `/home/user/.pindou-skill/`只是候选，必须结合实际宿主约定判断。不要照搬截图路径到其他宿主。
- 源码和`.venv`需位于同一稳定安装目录；作品单独存入宿主支持保留的项目目录。必要的入口软链接只作入口，不承担保存功能，不覆盖已有真实目录。
- 若宿主仅保留项目文件而不保留可执行环境，将完整技能包及作品备份保存到项目文件；临时执行环境失效后可能仍需重建依赖，不能承诺免安装。
- 若无任何持久化依据，提前说明“当前只能确认本次会话可用”，使用可下载的备份文件保留成果；不要连续尝试重装来冒充修复。只有确实无法确定目标目录时才向用户询问一次。

## 安装与复用

1. 查已记录的绝对安装路径，而不是只检查当前工作目录。源码根目录须有SKILL.md、scripts/pindou.py、requirements.lock及assets/。
2. 若已有`.venv/bin/python`，用该解释器和实际脚本绝对路径运行doctor。成功就复用已有环境，不再下载、创建虚拟环境或安装依赖。
3. 首次安装：从完整发布包或GitHub main分支取得完整文件树；校验包内MANIFEST.json，然后解压/复制到最终稳定目录。不要只复制SKILL.md，也不要把开发目录的用户作品、缓存和私人文件当技能发布。
4. 在最终目录创建`.venv`，按README用`python -m pip install --require-hashes -r requirements.lock`安装固定依赖，然后doctor。已有环境仅依赖缺失或不匹配时修复依赖；解释器失效或安装路径迁移时，保留旧环境，另建可用环境。不能直接搬迁旧虚拟环境后假定能用。
5. 首次安装耗时单独说明，不混入像素/PDF处理耗时。测试套件属于开发验收，不在每次生成时运行。
6. 将实际安装路径、作品路径、技能版本、检查结果与持久化依据记录在宿主确认保留的项目说明文件中，后续按记录调用。同一次会话不要反复询问或报告安装。

安装后只报告真实结果，例如：

> 环境检查通过，后续复用已有安装。技能：〈真实绝对路径〉；作品：〈真实绝对路径〉。宿主声明的保存范围：〈实际范围〉。

占位符须替换为真实检查结果。若只有本次会话验证，明确写本次会话可用，不写“永久保存”或“重启一定不会丢”。

## 临时目录重置后的恢复

1. 先查持久安装的实际绝对路径和解释器；它们仍可用时直接切换回该路径，仅恢复必要的临时入口，不重装。
2. 查原作品的state.json、revisions/、events.jsonl及原图。用原作品目录执行status；首次恢复执行validate。沿用原project_id、revision_id、网格和确认记录。
3. 安装缺失但项目文件保留时，从真实技能备份包恢复安装；作品独立保留，不因修复环境覆盖或重建作品。
4. 只有某部分依赖失效就修复该部分；解释器路径已变则在最终位置重建环境。若解释器版本或系统架构不同，不能复用旧二进制依赖。
5. 缺少真实作品文件时报告缺失项并恢复备份，不根据聊天、预览截图或记忆制造“同一版本”。

正常修改、取消、展示、确认和导出仍遵循原有阶段规则。本次修复不取消用户确认，也不修改图像算法。
